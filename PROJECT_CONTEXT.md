# Контекст CourseWorkBot для следующих сеансов

Обновлено: 2026-11-09. Перед работой прочитать этот файл, AGENTS.md и затронутые
спецификации. Этот файл — краткая передача состояния, а не замена кода и тестов.
Не записывать сюда секреты, пароли, коды подтверждения и личные Telegram ID.

## Проект и публикация

- Репозиторий: https://github.com/serg-358/CourseWorkBot, рабочая ветка
  `codex/modular-web-project`; публикация: push `HEAD:main`, без force.
- Публичный сайт: https://pc-doctor.duckdns.org, VPS Play2Go, Ubuntu 24.04.
- На VPS `/opt/courseworkbot`, бот и сайт в Docker Compose; общая SQLite
  в volume `courseworkbot_bot_data`, путь контейнеров `/data/bot_database.db`.
  PostgreSQL подготовлен как будущая возможность, переноса пока не было.
- Nginx проксирует HTTPS в `127.0.0.1:8000`, сертификат Let’s Encrypt,
  автоматическое продление включено. Секреты остаются в серверном `.env`.
- GitHub Actions `.github/workflows/ci-deploy.yml`: Ruff, pytest, Docker build,
  затем развёртывание проверенного SHA. На VPS root-скрипт
  `/usr/local/sbin/courseworkbot-deploy` вызывается ограниченным deploy-ключом.
- SSH с этого ПК настроен ключами в пользовательской `.ssh`; не печатать ключи.
  При диагностике GitHub fetch на VPS помогло локальное `http.version=HTTP/1.1`;
  настроены `http.lowSpeedLimit=100`, `http.lowSpeedTime=30`.
- Бэкап SQLite: `/usr/local/sbin/courseworkbot-backup.py` на VPS, сохраняет
  согласованные копии в `/var/backups/courseworkbot`, оставляет три. Регулярный
  период согласован: раз в две недели. Перед миграцией — отдельный бэкап.

## Реализовано и проверено

- Пакет `repair_bot/`: модели/CRUD в `database/`, сценарии в `handlers/`,
  сервисы AI/расчёта в `services/`, SQLite FSM; тонкий корневой `main.py`.
- Aiogram 3, SQLAlchemy 2; фото и AI-оценка; роли client/master/admin.
- Сайт FastAPI + Jinja2 (`web/templates`), обычный CSS и небольшой JS
  (`web/static`); React, Tailwind, HTMX/Alpine не подключены.
- Вход email/пароль (минимум 8 символов), подписанная HttpOnly-сессия, CSRF.
  Привязка: код из бота `/sitecode` (8 цифр, TTL10m, лимиты) вводится на сайте;
  прежняя команда `/link CODE` сохранена. Не переопределять существующие связи.
- Главные страницы по ролям, таблицы заявок, отдельные карточки и защищённые фото.
  Сортировки: номер, дата, статус, приоритет, цена; фильтры: статус, приоритет,
  диапазон дат. «Главная» кабинета — `/panel`, список — `?tab=requests`.
- Администратор может посмотреть client/master через `view=...`, реальная роль
  не меняется. В client-предпросмотре можно создать собственную реальную заявку.
- Telegram — компактная иконка в шапке с переходом `/bot` и QR `/bot-qr.png`.
- Обратная связь отправляется администраторам в Telegram только по отправке формы.
- Публичные `/services`, `/documents`, сценарий `/request/new` с продолжением
  после входа. «Мои заявки» очищены от повторного приветствия и телефона.
- Прайс работ/деталей берётся из действующего каталога клиентских цен (не затрат).
- Согласована гарантия 30 дней на работы. Настоящие документы о квалификации
  пользователь пока не предоставил; не создавать поддельные сертификаты/отзывы.
- Подарочный сертификат 1000 ₽ после завершённого ремонта от 15000 ₽ с проверенной
  мастером ценой; персональный, бессрочный, один на следующую заявку. Одноразовое
  применение, остаток не выплачивается. Резерв снимается при отмене, погашается
  при завершении. Учёт в `gift_certificates`, скидка едина в сайте и боте.
- Добавочная миграция `ops/migrations/20261108_gift_certificates.sql` уже применена
  локально и на VPS после бэкапа; исходные строки и колонки сохранены.
- Предыдущий стабильный серверный SHA до этой задачи: `8d00861`. Фактический релиз
  всегда сверять через GitHub Actions и `git rev-parse HEAD` на VPS.

## Изменения этого этапа

- Снимки деталей/инструментов к staff_edits; правки на сайте и FSM бота (`=` оставить,
  `-` очистить), сохраняются исходная AI-оценка, автор и история.
- Исправлен запрет создания собственной заявки у admin в client-предпросмотре.
  При отправке показан индикатор, после создания открывается карточка.
- Обратная привязка через `/sitecode`/кнопку и ввод 8 цифр на сайте; старый /link
  сохранён. Коды только в личном чате, HMAC, TTL10m, cooldown60s, 5 попыток/account
  и 20/IP на10m. Состояние лимитов в БД.
- Корзина с восстановлением, вкладки новых/в работе/завершённых/отменённых заявок.
- JSON и CSV экспорт текущей выборки; импорт с предпросмотром (200/512КиБ, TTL15m),
  идемпотентный и атомарный. Не меняет роли/профили, не выдаёт бонусы, не вызывает AI.
- Одна бесплатная AI-попытка на TG, следующие30₽, staff без лимита; общий шлюз
  сайта и бота. `/admin/ai` вручную выдаёт оплаченные попытки и компенсации с аудитом
  и защитой от повторного POST. Автоматической платёжной системы нет. ОшибкаAPI
  расходует попытку (админ выдаёт компенсацию), отсутствие настройки возвращает.
  Уже успешная оценка не перезаписывается. Фото хранится независимо от AI.
- Добавочная миграция восьми таблиц:
  `ops/migrations/20261109_access_and_transfer.sql`; без изменений исходных колонок.
  Уже применена локально и на VPS после онлайн-бэкапа; исходные строки/колонки
  и integrity_check сохранены. После обновления кода требуется перезапуск контейнеров.
- Проверки этого этапа: 89 тестов на временных БД, Ruff и pre-commit успешно.
  Реальные платные вызовы AI и приём платежей тестами не выполняются.

## Что ещё не реализовано

Автоматический эквайринг; PostgreSQL вместо SQLite; реальные квалификационные
документы мастеров. Не обещать эти функции как готовые. Сертификаты1000₽ и
гарантия30дней — уже согласованные условия, не менять без пользователя.

## Обязательные ограничения

Роли проверяются сервером, username/параметры URL не дают прав. Не менять .env,
не заменять рабочую БД локальной. Миграции — с бэкапом и тестом старой схемы.
Перед публикацией выполнять Ruff, pytest и pre-commit. На этом Windows ПК pytest
нужен явный `--basetemp .venv/pytest-temp`; для pre-commit:
`$env:PYTEST_ADDOPTS='--basetemp=.venv/precommit-temp'`.
При зависшем fetch на VPS проверить сеть и повторить только упавшее развёртывание.
