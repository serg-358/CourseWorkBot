# ПК Доктор — Telegram-бот для заявок на ремонт

Курсовой проект: асинхронный Telegram-бот для регистрации клиентов, учёта заявок на ремонт компьютерной техники и работы мастеров. Этот README — краткая карта проекта и рабочие инструкции для участников команды и следующих разработчиков/агентов.

Репозиторий: [serg-358/CourseWorkBot](https://github.com/serg-358/CourseWorkBot).

## Текущее состояние

Сейчас реализованы регистрация и профили, разделение ролей `client` / `master` / `admin`, создание и просмотр заявок, смена статусов, уведомление клиента о смене статуса, SQLite-backed FSM и административные списки/статистика. Мастер и администратор могут исправить диагноз и цену в карточке; исходная оценка ИИ сохраняется, а автор и время каждой правки записываются в историю. Отдельное FastAPI-приложение предоставляет кабинеты клиента, мастера и администратора с авторизацией email/паролем и привязкой аккаунта к Telegram одноразовой командой `/link`.

При создании заявки клиент выбирает срочность: обычная (0 ₽), срочная (500 ₽) или критическая (1 000 ₽). Доплата отображается отдельно от стоимости ремонта, а ориентировочный итог рассчитывается отдельно. Код тарифа, название и доплата сохраняются снимком в заявке, поэтому последующие изменения тарифа не переписывают историю.

AI-диагностика использует совместимый с OpenAI Chat Completions API KodikRouter:
клиент может добавить одно фото ошибки, а агент формирует предварительные
рекомендации и выбирает позиции из локального прайс-каталога. Сумму и наценку
15% рассчитывает приложение; итог подтверждает мастер. Добавьте
`KODIKROUTER_API_KEY` в локальный `.env`; `OPENAI_API_KEY` поддерживается только
как резервное имя переменной для существующей конфигурации.

## Стек

- Python 3.11.
- Aiogram 3.x, асинхронный long polling.
- SQLAlchemy 2.x async + SQLite (`aiosqlite`).
- FSM: собственное SQLite-хранилище в `repair_bot/fsm/`.
- Pytest и pytest-asyncio для проверок.
- Docker Compose для запуска в контейнере.

## Роли и доступ

| Роль | Что доступно |
|---|---|
| `client` | Создание заявки, список своих заявок, профиль |
| `master` | Все заявки, карточки заявок и смена статуса |
| `admin` | Пользователи и роли, все заявки, тарифы срочности, тексты кабинета, статистика |

## Навигация по экранам

Разделы, профиль, статистика, демонстрационные панели и карточки заявок открываются редактированием сообщения, на котором нажали inline-кнопку. Главное меню остаётся доступным на экранах разделов. Заявки показываются по одной с кнопками перехода к предыдущей и следующей; для мастера и администратора в карточке доступны действия по статусу. Повторный `/start` во время работы процесса переиспользует последний экран пользователя. Telegram-ошибка `message is not modified` обрабатывается без сбоя; после перезапуска бота первый `/start` создаст новый экран.

В диалогах регистрации и создания заявки вопрос бота также обновляется при переходе к следующему шагу. Сообщения пользователя с введёнными данными остаются в чате; отдельное уведомление клиенту отправляется при изменении статуса его заявки.

Начальные роли назначаются по числовым Telegram ID из `.env`: администраторы из `ADMIN_TELEGRAM_IDS`, мастера из `MASTER_TELEGRAM_IDS`; остальные пользователи получают роль `client`. Связанный веб-аккаунт может изменить роль пользователя только из кабинета администратора. Пользователи из начальных allowlist защищены от понижения роли. Если ID указан в обоих списках, приоритет у `admin`.

Все администраторы могут временно переключиться на демонстрационные панели мастера и клиента. Это меняет только отображаемое меню, не запись пользователя в БД и не его реальные права. Демонстрационный режим хранится в памяти и сбрасывается при перезапуске.

## Структура проекта

В корне оставлена тонкая точка входа `main.py`, а код приложения собран в пакетах:

```text
main.py                         # запускает приложение
repair_bot/
├── bootstrap.py                # конфигурация и запуск Aiogram polling
├── database/
│   ├── session.py              # engine, сессии и таблицы
│   ├── models/                 # сущности пользователей, заявок, оценок, правок и срочности
│   └── crud/                   # users.py, requests.py и pricing.py
├── fsm/                        # постоянное SQLite-хранилище состояний
├── handlers/
│   ├── registration.py         # запуск, регистрация и отмена диалогов
│   ├── client_requests.py      # создание и просмотр заявок клиента
│   ├── staff_requests.py       # очередь, фото и статусы заявок
│   ├── admin.py                # пользователи и статистика
│   └── common.py               # общие проверки и форматирование
├── keyboards/                  # меню и клавиатуры карточек заявок
├── states/                     # состояния регистрации и заявок
├── services/                   # AI-диагностика и прайс-каталог
├── web/                        # FastAPI-кабинеты и серверная авторизация по ролям
└── scripts/                    # явные команды обслуживания данных
tests/                          # изолированные проверки
```

## Настройка и локальный запуск

1. Установите Python 3.11.
2. Создайте виртуальное окружение и установите зависимости:

   ```powershell
   py -3.11 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install -r requirements-dev.txt
   ```

   Для автоматических проверок перед коммитом один раз установите Git hook:

   ```powershell
   pre-commit install
   ```

3. Скопируйте `.env.example` в `.env` и задайте значения:

   ```dotenv
   BOT_TOKEN=put_your_bot_token_here
   ADMIN_TELEGRAM_IDS=числовой_id_Ивана,числовой_id_Сергея
   MASTER_TELEGRAM_IDS=числовые_id_мастеров
   KODIKROUTER_API_KEY=ключ_с_правом_gateway:write
   KODIKROUTER_BASE_URL=https://api.kodikrouter.ru/v1
   KODIKROUTER_MODEL=openai/gpt-5.4-mini
   ```

   Если мастеров ещё нет, оставьте `MASTER_TELEGRAM_IDS` пустым. Если используется
   ранее созданная конфигурация, вместо `KODIKROUTER_API_KEY` допустим
   `OPENAI_API_KEY`. Для получения собственного числового ID можно временно
   воспользоваться ботом вроде `userinfobot`.

4. Запустите бота:

   ```powershell
   python main.py
   ```

Бот начинает работу через Telegram `/start`. Пользователь проходит регистрацию по имени и номеру телефона. Телефон приводится к формату `+7XXXXXXXXXX`. Команда `/cancel` отменяет текущую регистрацию или создание заявки.

Локальный сайт запускается отдельно:

```powershell
python -m repair_bot.web
```

Откройте `http://127.0.0.1:8000`. Зарегистрируйте email и пароль, затем
зарегистрируйтесь в боте и привяжите аккаунт одноразовой командой `/link`.
Сайт и бот читают один SQLAlchemy URL; если `DATABASE_URL` пуст, оба используют
локальную SQLite из `DATABASE_PATH`.

## Проверки

```powershell
python -m ruff check .
python -m pytest -q
```

Тесты работают на временной SQLite-базе и не изменяют рабочий `bot_database.db`.

Перед передачей изменений также выполните:

```powershell
python -m ruff check .
pre-commit run --all-files
```

`pre-commit` запускает Ruff и тесты перед каждым коммитом. Если hook не установлен,
эти же команды остаются доступными для ручной проверки.

## Запуск через Docker Compose

Создайте `.env` с настройками выше, затем:

```powershell
docker compose up --build -d
docker compose logs -f bot
```

Остановить контейнер:

```powershell
docker compose down
```

Данные SQLite лежат в именованном Docker volume `bot_data`. Для сброса этого тома нужна отдельная осознанная операция; обычный `docker compose down` данные сохраняет.

Для запуска на VPS установите Docker Engine и плагин Docker Compose, клонируйте репозиторий на сервер, создайте там `.env` с боевым токеном и числовыми ID ролей, затем выполните `docker compose up --build -d`. Проверяйте запуск командой `docker compose logs -f bot`. Токен хранится только в окружении сервера; входящие порты открывать не требуется, так как бот использует long polling.

### Play2Go VPS и автоматическое развёртывание

Рабочий сервер проекта: `31.76.20.98` (Ubuntu 24.04), каталог приложения — `/opt/courseworkbot`. Бот запускается Docker Compose как `courseworkbot-bot-1`; SQLite хранится в постоянном Docker-томе `courseworkbot_bot_data`, поэтому пересборка контейнера не удаляет регистрации и заявки. Серверный `.env` не берётся из Git и должен сохраняться при обновлениях.

Workflow `.github/workflows/ci-deploy.yml` проверяет Ruff и pytest для pull request в `main` и каждого push в `main`. VPS обновляется только после успешных проверок. Перед первым запуском workflow добавьте в GitHub репозитория секрет `DEPLOY_SSH_KEY`: полное содержимое приватного ключа `courseworkbot_actions` (его парная публичная часть установлена на VPS для пользователя `courseworkbot-deploy`). Не добавляйте ключи API и токен Telegram в этот секрет: они остаются только в серверном `.env`. Ключ деплоя ограничен серверным скриптом и принимает лишь SHA проверяемого текущего `main`.

Резервное копирование SQLite на VPS запускается systemd-таймером каждые 14 дней; хранятся три последние копии в `/var/backups/courseworkbot`. Копии находятся на том же VPS, поэтому не защищают от потери всего сервера; важные снимки следует периодически скачивать отдельно.

## Данные и изменение схемы

По умолчанию SQLite-файл — `bot_database.db` в каталоге проекта. Путь можно задать переменной `DATABASE_PATH`; в Compose используется `/data/bot_database.db`. При старте `create_tables()` создаёт отсутствующие таблицы, но **не выполняет миграции существующих таблиц**. При изменении полей моделей сначала продумайте миграцию и резервную копию базы.

Перед первым запуском версии с AI-оценкой на существующей базе выполните отдельную миграцию:

```powershell
python -m repair_bot.scripts.migrate_ai_assessments
```

Скрипт создаёт только таблицу AI-оценок, не изменяет существующие записи и перед этим создаёт резервную копию файла БД. Повторный запуск безопасен.

Основные сущности:

- `User`: Telegram ID, имя, телефон, роль, дата регистрации.
- `RepairRequest`: владелец, описание, статус, приоритет, даты создания/изменения и необязательная связанная AI-оценка.
- `RepairRequestAiAssessment`: фото Telegram, клиентская и мастерская оценки, коды прайс-каталога и расчётные суммы в копейках.
- `RepairRequestStaffEdit`: история подтверждённых исправлений диагноза и цены с автором.
- `UrgencyTariff` и `RequestUrgency`: тарифы доплаты и снимок выбранной срочности в заявке.
- `WebsiteAccount`, `TelegramLinkCode`, `RequestAddress` и `SiteText`: логин сайта,
  одноразовая привязка, необязательный адрес выезда для заявки и тексты кабинета.

## Подготовка PostgreSQL и сайта

`compose.web.yaml` включает PostgreSQL и сайт профилем `web`; обычный локальный и
текущий VPS-запуск через `compose.yaml` остаётся SQLite. Перед переключением
сервера создайте пустую PostgreSQL-базу, остановите запись в бота на время
переключения и выполните проверенный перенос по инструкции
[`specs/deployment/sqlite-to-postgres.md`](specs/deployment/sqlite-to-postgres.md).
Скрипт делает онлайн-копию SQLite, переносит строки в таблицы PostgreSQL и
сверяет число записей. Старый SQLite-файл и его резервная копия остаются на месте.

После переноса задайте на сервере `DATABASE_URL`, `POSTGRES_PASSWORD`,
`WEB_SESSION_SECRET`, `BOT_USERNAME` и `WEB_COOKIE_SECURE=1`. Затем запускайте
контейнеры с обоими compose-файлами и профилем `web`. Сайт публикуется только на
`127.0.0.1:8000`; перед внешним доступом нужен HTTPS reverse proxy и доменное имя.
Пример systemd-таймера сохраняет PostgreSQL dump и SQLite FSM раз в 14 дней,
оставляя три последние пары файлов на VPS: `ops/systemd/`.

Статусы заявок: `new`, `in_progress`, `completed`, `cancelled`. Новая заявка получает `medium`, пока успешная AI-оценка не установит иной приоритет.

## Инструкции для следующих разработчиков и агентов

- Перед правками сначала прочитайте этот README и проверьте фактический код обработчиков.
- Не читайте и не публикуйте `.env`; не вставляйте токены в исходный код, README, логи или Git.
- `.env`, SQLite-файл, логи, виртуальное окружение, IDE-кэш и тестовые артефакты должны оставаться вне коммитов.
- Проверяйте доступ по Telegram ID и роли из настроек, а не по username. Не считайте демонстрационный вид настоящей сменой роли.
- Любое изменение схемы БД требует решения о миграции; `create_all()` не заменяет миграции.
- После изменений запускайте `python -m ruff check .` и `python -m pytest -q`, сообщайте о непроверенных интеграциях.
- Не утверждайте, что Docker-развёртывание или VPS настроены, если соответствующий код/сервис не реализован и не проверен; AI-оценка требует заданного `KODIKROUTER_API_KEY` (либо резервного `OPENAI_API_KEY`) и отдельной проверки с реальным ключом.
- Перед изменением пользовательского сценария прочитайте `specs/features/repair-requests.md`; перед изменением схемы — `specs/data/database-schema.md`.
- Повторяемые рабочие процедуры Codex находятся в `.agents/skills/`, а материал для отчёта о харнесе — в `docs/harness-report.md`.

Файл `.env` исключён из Git. В репозиторий разрешено добавлять только `.env.example` с пустыми или демонстрационными значениями. Если токен бота когда-либо попал в переписку или репозиторий, отзовите его через BotFather и выпустите новый.

## Обновление сайта и бота

`compose.yaml` запускает бот и веб-кабинет с общей SQLite-базой в volume
`bot_data`. Сайт слушает только `127.0.0.1:8000` VPS; для браузерного доступа
нужен HTTPS reverse proxy. В серверном `.env` обязателен уникальный
`WEB_SESSION_SECRET` длиной от 32 символов. Серверные данные и `.env` не
заменяются локальными файлами при обновлении GitHub.

Главная страница использует Jinja2-шаблоны в `repair_bot/web/templates/`,
стили и автоматическое слайд-шоу — в `repair_bot/web/static/`.
Вымышленные отзывы и квалификационные документы не публикуются.
Пароль сайта содержит минимум 8 символов. После входа действия на главной
ведут в кабинет. Одноразовая команда `/link CODE` работает только при общей
базе сайта и бота. Локальные веб-аккаунты автоматически на VPS не переносятся.

## Каталог работ, гарантия и подарочные сертификаты

Публичный прайс `/services` и вкладка «Услуги и цены» используют клиентские цены
действующего каталога расчёта. «Описать проблему» ведёт в сценарий на сайте
`/request/new`, сохраняющий намерение создания при входе/регистрации.
Раздел `/documents` содержит согласованную гарантию 30 дней на работы. Подлинные
сертификаты квалификации не предоставлены; вымышленные документы не публикуются.

За завершённый ремонт от 15000 ₽ после проверки цены специалистом выдаётся
персональный бессрочный сертификат на 1000 ₽. Владелец применяет его к следующей
открытой заявке после проверки цены мастером. Сертификат резервируется, при
завершении погашается, при отмене освобождается. Учёт — в новой таблице
`gift_certificates`, без изменения колонок существующих таблиц. SQL-миграция
SQLite: `ops/migrations/20261108_gift_certificates.sql`. Перед миграцией нужен
бэкап; применить её следует до одновременного перезапуска бота и сайта.
Администратор видит общий журнал сертификатов на `/admin/certificates`, клиент —
только свои на `/panel?tab=certificates`. Одинаковый итог со скидкой показывается
на сайте и в Telegram. Остаток номинала не выплачивается, повторное списание
защищено проверкой владельца и ограничениями БД. Подробности в спецификациях.


## Заявки, корзина и доступ к AI

Администратор открывает `/admin/requests`: вкладки «Все», «Новые», «В работе»,
«Завершённые», «Отменённые» и «Корзина». Фильтры и сортировки применяются также
к экспорту JSON/CSV. В карточке доступно мягкое удаление и восстановление;
история ремонта, фото и сертификаты сохраняются. Клиент и мастер не видят корзину.

Импорт: `/admin/requests/import`, JSON версии 1 или CSV из экспорта сайта
(UTF-8 BOM, разделитель `;`). До 200 записей и 512 КиБ за один предпросмотр;
большой архив разделите фильтрами перед экспортом. После проверки показаны
новые записи и число дублей; подтверждение действует 15 минут и однократно.
Номера в новой базе назначаются заново, исходные данные сохраняются. Новый
владелец получает только роль клиента, существующие профили/роли не меняются.
Импорт не запускает AI, не переносит пароли, права, кредиты или бонусные балансы
и не позволяет выдавать сертификаты по импортированным ремонтам. Имеющиеся
AI-оценки и история правок переносятся как исторические данные.

Сайт и бот используют одну квоту: одна бесплатная AI-попытка на Telegram-аккаунт,
следующие — 30 ₽. Мастер и администратор не ограничены. При отсутствии квоты
заявка всё равно сохраняется вместе с фото и передаётся мастеру. В карточке
можно запустить доступную диагностику после получения кредита. Уже готовая
AI-оценка не перезаписывается. Отсутствие настройки провайдера возвращает резерв;
ошибка внешнего API расходует попытку, служебную компенсацию выдаёт администратор.
Квота не возвращается при удалении заявки или повторной регистрации того же TG.

`/admin/ai`: ручная выдача оплаченных попыток после проверки оплаты либо
служебной компенсации (0 ₽). Автоматическая платёжная система не подключена.
Выдачи сохраняют автора, количество и сумму; повторный POST той же формы не
удваивает баланс. Исторические успешные оценки засчитываются в бесплатный лимит.

Мастер и администратор исправляют диагноз, цену, детали и инструменты в карточке
сайта или через FSM бота. Оригинал AI и снимки правок с автором/временем сохраняются.
В Telegram `=` оставляет поле, `-` очищает. Администратор в режиме клиента может
создать собственную реальную заявку; роль администратора не меняется.

## Привязка сайта с телефона

В личном чате с ботом нажмите «🔑 Код для сайта» или отправьте `/sitecode`.
Введите 8 цифр в кабинете сайта: код действует 10 минут, выдаётся не чаще раза
в минуту; до 5 попыток аккаунта и 20 с одного IP за 10 минут. В БД хранится HMAC,
коды одноразовые. Старый способ — команда `/link CODE` с сайта в бота — сохранён.
Уже связанный Telegram нельзя привязать к другому аккаунту. Рабочая БД и секреты
бота/сайта должны быть общими.
