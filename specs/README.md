# Spec-Driven Development

Спецификации — источник согласованного поведения бота до изменения кода.
Они не заменяют тесты, а помогают выбрать минимальное корректное изменение.

## Правило работы

1. Перед изменением пользовательского сценария прочитайте файл из `features/`.
2. Перед изменением моделей, таблиц или SQL-запросов прочитайте файл из `data/`.
3. Если меняется наблюдаемое поведение или схема, обновите соответствующую спецификацию и тесты в одной задаче.
4. Не включайте в спецификации функции, которых нет в проверенном коде. AI-диагностика описывается только после проверки её кода и тестов.
