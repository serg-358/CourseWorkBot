# Агентский харнес CourseWorkBot

## Что используется

| Компонент | Файл | Назначение | Проверка |
| --- | --- | --- | --- |
| Постоянные инструкции | `AGENTS.md` | Архитектура, безопасность, тестирование и правила работы Codex | Открыть файл в корне репозитория |
| Skills | `.agents/skills/*/SKILL.md` | Процедуры изменений сценариев, схемы БД, проверки и стресс-теста архитектурных решений | Показать папки и YAML front matter |
| SDD | `specs/` | Зафиксированное текущее поведение заявок и схема данных до изменения кода | Сопоставить с `handlers/`, `models.py`, `crud/` |
| MCP | `.codex/config.toml` | Read-only доступ к официальной документации OpenAI | `codex mcp list` в доверенном проекте |
| Quality gate | `.pre-commit-config.yaml` | Ruff и pytest перед коммитом | `pre-commit run --all-files` |

## Процесс разработки

1. Перед задачей разработчик или Codex читает подходящую спецификацию и skill.
2. Изменение выполняется в существующих слоях: обработчик проверяет ввод и права,
   CRUD работает с данными, тест проверяет наблюдаемое поведение.
3. Перед передачей результата запускаются Ruff, pytest и pre-commit.
4. Если проверка не проходит, изменение исправляется и проверка повторяется.

Перед VPS-развёртыванием, миграцией БД, AI-интеграцией или добавлением инвентаря
используется `grilling`: он собирает требования вопросами по дереву решений и не
позволяет начать реализацию, пока пользователь не подтвердит согласованный план.

Это один управляемый процесс разработки, а не оркестрация нескольких моделей.
Многоагентный pipeline и Agents API в проект не добавлялись, поскольку они не
нужны для текущего Telegram-бота и усложнили бы сопровождение.

## Команды демонстрации

```powershell
python -m pip install -r requirements-dev.txt
pre-commit install
python -m ruff check .
python -m pytest -q
pre-commit run --all-files
codex mcp list
```

MCP `openaiDeveloperDocs` применяется только к вопросам о продуктах OpenAI и не
получает токен бота, содержимое `.env` или данные пользователей.
